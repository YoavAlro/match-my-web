# Tweaksy Live demo script

Target length: 2:35–2:50. Record in English, with narration, no background music, and no unrelated tabs or third-party marks on screen.

## 0:00–0:18 — Problem and product

**Screen:** Open the production URL on Harborline Journal. Slowly show the dense six-story grid and fixed Tweaksy dock.

**Narration:** “Websites are designed once, but people’s visual needs change. Tweaksy Live lets a person and their agent reshape the same page safely. The agent proposes; the person sees, approves, or undoes.”

## 0:18–0:38 — Real-site free-form chat

**Screen:** Briefly show Tweaksy’s Chrome side panel over a normal website. Type: “Make this calmer, show one article at a time, and reduce motion.” Show the proposal and preview on the actual page.

**Narration:** “This isn’t an iframe or a fake editor. On a permitted website, I talk to Tweaksy in free-form text. It maps my request to safe visual primitives, previews the change on the real page, and waits for me to approve.”

## 0:38–1:00 — Discover the tools

**Screen:** In ChatGPT’s in-app browser, open Site tools and show the five Tweaksy tools. Ask: “Inspect this Tweaksy page and tell me what you can safely adapt.”

**Narration:** “The public Harborline page is the no-install fallback. Its top-level page publishes five focused WebMCP tools, so judges can test the same preview contract immediately.”

## 1:00–1:35 — Agent creates the hero preview

**Screen:** Ask: “Make this calmer for focused reading: one story at a time, larger text, less motion, and strong keyboard focus. Preview it; don’t save it.” Let the agent inspect state and call the preview tool.

**Narration:** “ChatGPT translates a human need into several coordinated changes in one call. The tool requires the current revision, applies only vetted fields, and returns preservation evidence. It cannot send CSS, HTML, scripts, URLs, selectors, or content deletions.”

## 1:35–1:58 — Inspect the shared result

**Screen:** Show the adapted page, the unsaved preview card, and “6 available · 1 shown” proof. Navigate once with the next button, then click or Shift-Tab to focus the story deck and use the right arrow key.

**Narration:** “The result is not a hidden automation claim—it is the page we both see. All six stories remain, the deck works with keyboard controls, and the stable dock says this is still unsaved.”

## 1:58–2:18 — Human approval and persistence

**Screen:** Click **Approve** manually. Reload the page to show the approved design persists. Then click **Restore original page**.

**Narration:** “I approve the exact visible preview. Only the declarative design is stored, locally in this browser. A reload restores it, and one click returns to the untouched original.”

## 2:18–2:42 — Architecture and close

**Screen:** Briefly show `src/real-page-webmcp.ts`, `src/web/webmcp.ts`, and the passing test summary, then return to the app/social card.

**Narration:** “Real pages expose only inspect, preview, and undo—never credentials, permissions, or persistence. The hosted dock adds a fully testable approval loop. Automated tests enforce both boundaries. Tweaksy makes agentic adaptation visible, reversible, and genuinely collaborative.”

## Recording checklist

- Use the final production deployment, not localhost.
- Keep the video below 3:00; aim for 2:45.
- Ensure tool names and returned preservation evidence are readable at 1080p.
- Demonstrate a real WebMCP call, not only the manual preset.
- Show audio waveform or verify narration before upload.
- Upload as a **public** YouTube video.
- Put the production URL and repository URL in the video description.
- Do not change the demo deployment after the submission deadline.
